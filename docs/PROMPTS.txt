Built with Claude (Anthropic) as a pair-programmer in a single chat session.
================================================================================

1. INITIAL BRIEF
--------------------------------------------------------------------------------
Prompt:
"given is my assignment for power labs to make an exact airbnb app use angular
for frontend and java for backend, it should be same as the vercel link"
(assignment document attached)

Result:
Claude read the assignment doc and tried to fetch the reference Vercel URL
directly. The URL was not reachable through available tools (not indexed by

Rather than guess at a generic Airbnb layout and call it "exact," Claude

proceeding blind.

2. REFERENCE SCREENSHOTS
--------------------------------------------------------------------------------
Prompt:
11 screenshots of the reference listing page — full page (hero grid, sidebar,
amenities, calendar, reviews, host, things-to-know, nearby stays) and the full
"Photo tour" overlay (category thumbnails + per-room sections).

Result:
Claude read the layout, copy, section order, and interactions (tabs, "Show all
photos," "Show all amenities," "Show all reviews," modal overlay) directly off
the screenshots and used them as the spec for every component built after —

3. FIRST BUILD (ANGULAR)
--------------------------------------------------------------------------------
Continuation of the above — build the full Angular + Spring Boot project
matching what the screenshots showed.

Result:
- Angular 18 standalone-component app, one component per section, with a
  ListingService that calls the backend and falls back to an in-memory mock.
- Spring Boot 3 REST API (JPA entities -> DTOs -> mapper -> controller),
  seeded on startup with the screenshot data.
- Docker Compose wiring frontend + backend + Postgres.
- Architecture doc and this prompt log.
- The Angular app was installed and built (npm install, dev and prod builds)
  successfully inside the sandbox. The backend could not be compiled in the
  sandbox (no network access to Maven Central).

4. FRAMEWORK SWITCH (ANGULAR -> REACT)
--------------------------------------------------------------------------------
Prompt:
"angular is not supported on intelliJ use react for frontend and make a new
zip file"

Result:
Claude rebuilt the frontend from scratch as React 18 + Vite + TypeScript,
keeping the same component breakdown, section order, copy, and visual design
as the Angular version, so the screenshot-derived fidelity carried over
1:1. Angular @Input() props became React props, Angular services became a
fetch-based service module, structural directives (*ngFor/*ngIf) became plain
JSX. Backend, Docker setup, and docs were updated to reference React; the
backend code itself did not need to change. Installed and built successfully
(npm install && npm run build, including full type-check) inside the sandbox.

5. BACKEND BUG REPORT AND FIX
--------------------------------------------------------------------------------
Prompt:
Pasted the full `mvn spring-boot:run` console log from the user's machine,
showing a Hibernate startup failure:
"org.hibernate.MappingException: Column 'rating' is duplicated in mapping for
entity 'com.mirashya.airbnbclone.model.Listing'"

Result:
Root cause: the `Listing` entity and its `@Embedded Host` both had fields
named `rating` and `reviewCount`, which Hibernate mapped to the same columns
by default. This is exactly the class of bug the unverified backend was at
risk of, since the sandbox could not run Maven.

Fix: added @AttributeOverrides on the `host` field in Listing.java, giving
every Host column a `host_` prefix (host_rating, host_review_count, etc.) so
they no longer collide with Listing's own columns. Also manually audited the
rest of the codebase for the same pattern (Host is the project's only
@Embeddable, so this was the only place it could occur) before repackaging.

6. FOLLOW-UP Q&A (for the assignment writeup)
--------------------------------------------------------------------------------
User asked Claude to describe, for submission purposes:
- how long the work took and what took the most time
- the implementation steps followed
- how code quality was ensured, and what was skipped

Claude's answers (summarized, in Claude's own words, not verified against a
clock):
- No wall-clock timer available; by volume of work, building ~15-20 frontend
  components twice (once in Angular, once in React) was the largest chunk of
  effort, ahead of the backend.
- Steps: read brief -> hit dead end on reference URL -> used screenshots as
  spec -> built frontend + backend in parallel against a shared data contract
  -> verified frontend builds in-sandbox -> delivered docs -> handled the
  Angular->React switch and the Hibernate bug as follow-ups.
- Quality measures: real npm builds (not just code review) for both frontend
  versions, a shared Listing type/DTO contract, mock-data fallback in the
  frontend, manual entity-mapping audit in place of a backend build, honest
  documentation of what was/wasn't verified.
- Skipped: real listing photos (placeholders used; reference photos are
  proprietary), booking/payment transaction logic, automated tests, and
  backend build verification (the gap that caused the Hibernate bug).
